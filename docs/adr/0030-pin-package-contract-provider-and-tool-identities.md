# Pin all design dependencies and migrate only through explicit cloning

Before the first stable `1.0` baseline, the product may remove or replace old Project schemas, Contracts, core implementations, and Package/tool interfaces without an importer; pre-release projects carry no continuing compatibility guarantee. Starting at `1.0`, each `.nocproj` pins exact Bundle digests for NoC Package, Contracts, immutable Default Engine, Runtime Closures, Extension Provider, DRC, and Generator plus their Host/protocol contracts. IDs/versions are metadata and compatibility versions classify migration only. Missing, revoked, mismatched, or incompatible dependencies open only in degraded inspect mode with no fallback. Post-`1.0` upgrades never happen silently: Package identity migration normally uses Clone and Migrate, while Default Engine migration uses an explicitly confirmed atomic candidate transaction with inverse Undo.
